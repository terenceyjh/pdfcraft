## 设计

沿用唯一 Session 和每视图独立 UI/渲染器。文档编号只确定编辑对象，视图编号确定窗口；不能再以文档编号充当窗口身份。内部分窗使用 egui 原生子窗口容器，保持单进程共享文档，避免副本同步与磁盘竞争。新增视图时自动平铺，之后可拖动、缩放或重新排列。键盘操作只作用于选中的子窗口，保存提示与未发布草稿不能被关闭操作绕过。

## 使用方法

1. 运行 `target/debug/pdfcraft.exe`。新设置默认简体中文；已有明确语言选择会保留，可在“首选项 → 界面语言”选择“简体中文”。本机便携测试设置已切换并保存为中文。
2. 打开 PDF，选择“视图 → 在软件内新建窗口”，或右键文档标签选择同名命令。重复操作会继续添加视图。
3. 打开另一份 PDF 后，它显示在主视图；也可为它新建内部窗口。工作区顶部的“在软件内新建窗口”菜单可从全部已打开 PDF 中选择，同一文件可反复选择。
4. 拖动子窗口标题栏移动，拖动右下角缩放；使用“平铺文档窗口”或“层叠文档窗口”重新排列。这两个命令也在“视图”菜单。
5. 在各窗口独立翻页、缩放、搜索、批注。窗口内“注释”按钮打开自己的笔记面板；输入后按回车发布，发布后其他视图立即可见。小窗阅读可用“单页完整显示”。
6. 使用各窗口的保存/另存为和撤销/重做；同文件共享修改与保存目标，不同文件互不修改。只有最后一个视图关闭时才需要处理已修改文档的保存提示；未发布的草稿需先发布或清空。

“视图 → 在新窗口中打开”仍创建独立系统窗口，重复操作也支持多开。“显示主窗口”可以恢复隐藏的主界面。

窗口布局和额外视图暂不跨重启恢复；独立进程的 `--new-window` 不参与共享。中文化针对软件界面，文件名、PDF 原文、用户笔记、标准缩写和品牌名保留原文。完整编辑面板在主视图；额外视图提供阅读与批注常用工具。

## 调试与控制

沿用显式启用、回环认证的 `--control` 通道，不新增监听端口。

- `ui.window {action:"open", doc:1, kind:"embedded"}`：软件内新视图；`kind:"native"` 为独立系统窗口。
- `ui.window {action:"state"}`：每个条目有唯一 `view` 和共享的 `doc`，不再用文档编号当窗口编号。
- `ui.window {action:"set", view:2, key:"page", value:3}`：定位某个视图；也支持 `focus/command/close`。
- 内部窗口共用主界面的控件树、输入和截图；可用 `window:<view>` 定位 `state/set/command`。原生额外窗口保留目标化输入与检查，原生 immediate/WGPU 截图限制仍存在。
- `view.new_pane/view.new_window/view.tile_windows/view.cascade_windows` 是统一命令；命令编号和自动化协议保持英文。
